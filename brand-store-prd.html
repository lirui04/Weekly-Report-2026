一、项目概述

1.1 项目背景

58同城面向品牌连锁门店客户推出「品牌门店协议」合作模式。品牌商总部与58签约后，旗下自营门店及加盟门店即可通过专属二维码自助采购招聘产品。当前缺少完整的线上化付费提单流程支撑此业务模式的规模化运营。

1.2 核心目标

目标描述KPI
降低接入门槛品牌门店扫码→认证→支付全流程 5 分钟内完成，无需人工销售介入<5min
财务闭环门店独立支付、独立UID，回款自动归属品牌商总部超管母账号100%
合规保障电子版「58网络服务单」在线签署，LBS 位置认证防止虚假注册上线
多产品可扩展首期 3 款产品，架构上支持未来品类扩展与价格调整可扩展

1.3 项目范围

本期范围（MVP）

包含：扫码入口 · LBS 定位认证 · 新UID生成与品牌关联 · 3款产品选择页 · 微信支付 & 支付宝支付 · 58网络服务单电子确认书 · 支付成功页 · 回款归属逻辑

不含：品牌商总部管理后台（已有） · 退款流程（下期） · 发票开具（对接现有发票系统） · 定向邀约/优惠券（下期）

五、功能规格

5.1 扫码入口与参数解析

功能描述

门店扫码后进入 H5/小程序页面，URL 携带以下参数：

参数说明示例
brand_id品牌商唯一标识BR20260001
channel渠道来源（可选）wechat_qr
sales_id绑定销售/渠道ID（可选）S10023
timestamp生成时间戳，防过期1722902400
sign参数签名，防篡改md5_hash

5.2 LBS 位置认证

功能描述

流程：页面加载 → 请求GPS定位权限 → 调用地图API获取省/市/区 → 自动填充门店地址 → 用户确认或手动修正 → 提交认证

地图服务：对接高德地图 JS API / 腾讯位置服务，获取精确地理位置（含省市区三级）

异常处理：定位失败 → 用户可手动搜索地址 → 人工审核标注 → 仍可继续流程

UID生成规则：BR_{brand_id}_{city_code}_{timestamp_short}，例如 BR_001_010_240806

5.3 产品选择与展示

展示逻辑

- 默认以卡片列表形式展示 3 款产品，支持左右滑动切换

- 免费试用包仅对「未购买过试用包的门店」展示，"已试用"状态显示为灰色禁用

- 推荐标记："月度简历宝"显示「热门」标签

- 权益详情展开/收起交互，避免信息过载

- 底部固定「立即购买」按钮，选中产品后高亮激活

5.4 支付与签约

支付页功能

支付方式：微信支付（JSAPI/小程序支付）+ 支付宝（手机网站支付），系统自动检测微信环境优先展示微信支付

58 网络服务单确认函：

  • 展示完整服务协议文本摘要 + 「查看完整协议」链接
  • 用户需勾选「我已阅读并同意《58网络服务单》」复选框
  • 勾选后方可点击「确认支付」按钮
  • 签署记录与UID关联存储，支持事后调取

5.5 支付成功与权益生效

成功后逻辑

- 回调通知后端更新订单状态 → 激活UID对应产品权益 → 服务期开始计时

- 回款归属：该UID在服务期内的所有消费/续费产生的回款，自动计入品牌商总部「超管顶级母账号」的业绩统计

- 成功页展示：订单号、产品名称、服务有效期、总部名称、下一步引导（发布职位）

七、界面设计方案

完整的 UI 原型以独立 HTML 文件交付，包含四屏核心界面：

页面核心内容设计要点
1. LBS 认证页定位授权 → 自动获取地址 → 确认/修正 → 展示品牌信息 → 生成UID简洁渐进，降低流失；地图点位可视化
2. 产品选择页3款产品卡片（推荐标记）→ 权益详情展开 → 选中确认卡片式对比，突出性价比；免费试用显眼入口
3. 订单确认 & 支付页订单摘要 → 支付方式选择 → 服务确认函签署 → 支付按钮信息层级清晰，支付安全感强；确认函合规
4. 支付成功页成功状态动画 → 订单信息 → 服务有效期 → 品牌归属 → 下一步引导正向情绪反馈，明确下一步行动指引

八、非功能需求

8.1 性能

  • 页面首屏加载 ≤ 2秒（4G网络）
  • 支付结果回调延迟 ≤ 3秒
  • 接口可用性 99.9%

8.2 安全

  • 二维码参数签名校验（MD5 + 时间戳防过期）
  • 支付接口全链路 HTTPS 加密
  • 服务确认函签署记录不可篡改
  • 接口防刷：单门店单日创建订单上限 10 次

8.3 兼容性

  • 微信内置浏览器（iOS/Android）
  • Safari / Chrome 最新两个大版本
  • 屏幕宽度适配：320px ~ 428px（移动端优先）
